# AI DEVELOPMENT QUALITY POLICY

1. Inspect before modifying.
2. Reuse existing patterns before creating new abstractions.
3. Prefer minimal changes.
4. Do not modify unrelated code.
5. Do not introduce dependencies without justification.
6. Never invent APIs, files, configuration or system behavior.
7. Every implementation must include verification.
8. Tests must cover success and failure paths.
9. The authoring agent cannot be the sole reviewer.
10. Report evidence, not confidence.
11. Large diffs require architectural justification.
12. Security-sensitive changes require separate security review.
13. A task is not DONE until acceptance criteria pass.
14. Preserve backwards compatibility unless explicitly approved otherwise.
15. Document important architectural decisions.
